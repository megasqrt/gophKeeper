# 🛡️ GophKeeper

---

Безопасный **менеджер паролей и секретов** с **клиент-серверной архитектурой**, написанный на **Go** с **TUI-клиентом** и **gRPC-сервером**.  
Цель проекта — предоставить **приватное, самодостаточное решение** для управления конфиденциальными данными (пароли, банковские карты, заметки, бинарные файлы) с сильной криптографией и синхронизацией между устройствами.

---

## ✨ Возможности

- 🔑 **Безопасное хранение данных** (учетные данные, банковские карты, текстовые заметки, бинарные файлы)
- 🔒 **Шифрование на клиенте** с использованием **AES-GCM** и **scrypt** для ключей
- 🖥️ **Терминальный интерфейс (TUI)** на базе [Bubble Tea](https://github.com/charmbracelet/bubbletea)
- 🌍 **gRPC-сервер** с TLS и JWT-аутентификацией
- 🔄 **Двусторонняя синхронизация** между клиентом и сервером
- 🗄️ **SQLite** на клиенте, **PostgreSQL** на сервере
- 🐳 Полная контейнеризация через **Docker & Docker Compose**
- ⚡ Архитектура с разделением на слои (domain, services, storage, transport)
- 🔐 Мастер-ключ для дополнительного шифрования чувствительных данных
- 📱 Поддержка нескольких устройств с синхронизацией

## 🏛️ Архитектура

```
   ┌───────────────────────┐       ┌───────────────────────┐
   │        Клиент         │       │        Сервер          │
   │  - TUI (BubbleTea)    │  gRPC │  - Auth (JWT, HMAC)    │
   │  - Local SQLite (E2EE)│ <────>│  - Sync (Postgres)     │
   │  - Sync Service       │       │  - User management     │
   │  - Encryption Service │       │  - Device management   │
   └───────────────────────┘       └───────────────────────┘
```

- **Клиент** хранит все данные локально в зашифрованном виде (SQLite с AES-GCM)
- **Сервер** управляет синхронизацией и аутентификацией пользователей
- **gRPC API** предоставляет методы для аутентификации, синхронизации и работы с данными

## 🧩 Технологии и инструменты

- **Язык**: Go 1.21+
- **UI**: [Charm BubbleTea](https://github.com/charmbracelet/bubbletea)
- **Базы данных**:
    - Клиент → SQLite с шифрованием AES-GCM
    - Сервер → PostgreSQL с pgx
- **Протоколы**: gRPC
- **Криптография**: AES-GCM, scrypt, JWT (HMAC-SHA256)
- **DevOps**: Docker, Docker Compose, Makefile

## 🚀 Быстрый старт

### Требования

- Go 1.21 или выше
- Docker и Docker Compose (для сервера)
- PostgreSQL (для сервера) или используйте Docker Compose

### Установка

1. **Клонируйте репозиторий:**
```bash
git clone <repository-url>
cd gophKeeper
```

2. **Запустите сервер с помощью Docker Compose:**
```bash
docker-compose up -d
```

3. **Соберите и запустите клиент:**
```bash
cd client
go build -o gophkeeper ./cmd/main.go
./gophkeeper
```
    или воспользуйтесь собранными клиентами
- gophkeeper-darwin-amd64 macOS intel
- gophkeeper-darwin-arm64 macOS arm
- gophkeeper-linux-amd64  linux
- gophkeeper-windows-amd64.exe windows

### Первый запуск

1. При первом запуске клиента создайте локальный пароль для разблокировки хранилища
2. Зарегистрируйтесь на сервере через меню "Register to server"
3. После регистрации данные будут автоматически синхронизироваться

## 📋 Основные функции

### Клиент

- 🔐 **Локальное шифрование** — все данные шифруются перед сохранением
- 📝 **Управление паролями** — создание, редактирование, удаление учетных записей
- 💳 **Банковские карты** — безопасное хранение данных карт
- 📄 **Текстовые заметки** — хранение конфиденциальных текстов
- 📁 **Бинарные файлы** — загрузка и синхронизация файлов
- 🔄 **Автоматическая синхронизация** — фоновая синхронизация каждые 10 минут
- 🔑 **Мастер-ключ** — дополнительный уровень шифрования для чувствительных данных

### Сервер

- 👤 **Управление пользователями** — регистрация, аутентификация, авторизация
- 🔐 **JWT-токены** — безопасная аутентификация с токенами
- 📱 **Управление устройствами** — поддержка нескольких устройств на пользователя
- 🔄 **Синхронизация данных** — двусторонняя синхронизация с разрешением конфликтов
- 🗄️ **Хранение данных** — надежное хранение в PostgreSQL
- 🔒 **TLS-шифрование** — защищенное соединение между клиентом и сервером

## 🧭 Философия и принципы

- **Безопасность прежде всего**: Все данные шифруются на клиенте перед отправкой. Сервер никогда не видит открытый текст.
- **Простота**: Минимум зависимостей, чистый Go-код, простой TUI-интерфейс.
- **Портативность**: Кроссплатформенные клиенты, самодостаточный сервер.
- **Устойчивость**: Синхронизация спроектирована для работы в офлайн-режиме.
- **Прозрачность**: Открытый исходный код с четкими границами между слоями.
- **Тестируемость**: Интерфейсы для криптографии и хранилища позволяют легко создавать моки.

## 🔧 Конфигурация

### Клиент

Конфигурация клиента хранится в `~/.gophkeeper/gpk.yaml`:

```yaml
server_address: localhost:8080
db_path: ~/.gophkeeper/gophkeeper.db
ca_cert_path: ~/.gophkeeper/certs/ca.crt
log_path: ~/.gophkeeper/client.log
user: <username>
```

### Сервер

Конфигурация сервера через переменные окружения или файл конфигурации (см. `server/internal/config/`).
